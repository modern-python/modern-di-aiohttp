# Change: Don't leave the request container in the aiohttp request

**Lane:** lightweight — 4 LOC net in one module, one added test, no public-API
change.

## Goal

Every request through `di_middleware` left a reference cycle behind, so the
per-request container and everything it reached could only be reclaimed by the
garbage collector, never by reference counting.

Measured over 100 requests against a real `aiohttp` server, GC disabled during
the run:

| modern-di | this integration | cyclic objects per request |
|---|---|---|
| 3.1.1 | as-is | 21.9 |
| **3.1.1** | **with this change** | **0** |

Bare aiohttp with no DI produces **0**, so all of them were ours.

## Approach

There were two independent cycles and both had to go:

1. `container → _scope_map → container` — every `Container` stored itself in its
   own scope map. Fixed upstream in modern-di 3.1.1.
2. `container → context → Request → request mapping → container` — **ours.** The
   middleware binds the `Request` into the container's context and then stores
   the container back into that same request via
   `request[_CONTAINER_REQUEST_KEY]`.

This change breaks the second: the entry is removed when the request finishes,
in a `finally` so it also runs when the handler raises. The container is already
bounded by the `async with` around it, so nothing may read the entry after that
block exits — the entry outliving the request was the bug, not a feature.

Found by auditing all 12 modern-di integrations that build per-request
containers. `modern-di-starlette` had the same defect (fixed in its 3.1.0);
`fastapi`, `litestar`, `taskiq` expose the container through a yield dependency
and never store it back; `flask`, `aiogram`, `faststream` store it somewhere the
context cannot reach; `celery`, `arq`, `typer` pass no context at all; `grpc`
keeps the child in a contextvar that the `ServicerContext` cannot reach.

## Files

- `modern_di_aiohttp/main.py` — `di_middleware` clears `_CONTAINER_REQUEST_KEY`
  in a `finally`.
- `tests/test_middleware.py` — test that a completed request leaves no cyclic
  garbage and that the entry is gone afterwards.
- `pyproject.toml` — `modern-di` floor `>=3,<4` → `>=3.1.1,<4`. Required, not
  cosmetic: the new test fails against 3.0.0, which the old range permitted.
